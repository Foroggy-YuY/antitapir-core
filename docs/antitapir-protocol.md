# Anti-Tapir Core: протокол v1

Реализованный транспорт: унаследованные анонимные pipes дочернего процесса.
Windows named pipe пока не требуется: контроллер непосредственно запускает Core
с теми же правами. Не открываются TCP/UDP-порты управления, нет общего XOR-ключа.
Переход к отдельному повышенному helper для GUI потребует отдельного решения.

## Запуск

`antitapir-core.exe managed -c <полный путь к JSON> --control-timeout 60s`

Путь передаётся отдельным аргументом, содержимое конфига — в локальном файле.
`-c stdin` в managed-режиме запрещён: stdin занят управлением.
Наличие файла не означает импорт и адаптацию: этот пакет принимает уже совместимый JSON.

`antitapir-core.exe core-info` возвращает JSON с именем, версией Core,
версией протокола, версией базы и сопровождающим. TUN не запускается.
`antitapir-core.exe check -c <файл>` проверяет внешний конфиг без запуска TUN.

## Сообщения

UTF-8 JSON, одно сообщение на строку, максимум 4096 байт со стороны клиента.
stdout дочернего процесса используется только для событий, stdin — для команд.
Версия протокола — целое число `1`; таймаут старта ограничен контроллером и Core.

Контроллер отправляет:

```json
{"protocol":1,"type":"start"}
{"protocol":1,"type":"stop"}
```

Core отправляет последовательность:

```text
hello → config_accepted → ready → stopping → stopped
```

Каждое событие содержит `protocol`, `type`, `version`.
`config_accepted` означает разбор конфига, `ready` — завершение `instance.Start()`.
Доступность HTTP через VPN проверяет контроллер отдельно; игровой маршрут
и успешный вход эти события не подтверждают.

При ошибке событие `error` содержит один фиксированный `code`:
`start_timeout_or_channel_closed`, `protocol_mismatch`, `invalid_command`,
`startup_failed`, `startup_timeout`, `shutdown_failed`, `shutdown_timeout`.
Содержимое ошибок парсера и параметры серверов по каналу не передаются.
Прерванный запуск может завершиться `stopping → stopped → error` без `ready`.

## Завершение и ограничения

- Команда stop во время запуска отменяет контекст и закрывает частично созданный Box.
- EOF на stdin отменяет работу и запускает тот же путь закрытия.
- Core посылает stopped после завершения Close. При успешной остановке код процесса 0.
- Контроллер ограниченно ждёт подтверждение, затем завершает только собственный
  процесс. Windows job object остаётся последней страховкой.
- Windows mutex ограничивает контроллер одним экземпляром в сессии.
- Ошибки startup в v1 намеренно обобщённые; подробные безопасные категории — дальнейшее развитие.
- В managed v1 произвольные runtime-логи импортированного конфига отключены,
  чтобы не смешать stdout с протоколом и не записать секреты из тегов/URL.
  `logs/core.log` содержит только проверенные события жизненного цикла.
- Стандартный `run` оставлен для разработки; он не использует протокол контроллера.

## Проверка без VPN

`examples/core-smoke.json` не содержит TUN, listener, сервера или реквизитов.
На нём проверяются внешняя конфигурация, ready/stop, EOF и запуск упакованного Core.
Unit-тесты Go проверяют версию, неправильные команды, повреждённые/большие
сообщения, таймауты и отмену запуска. Python проверяет свой deadline, ограничение
сообщений, редактирование полей событий и работу с настоящим дочерним процессом.
